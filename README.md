## Завдання та реалізація

Планувальник синхронно повторює задачу при вказаних винятках.
Політика затримки передається як Callable; очікування, логер і годинник
можна підмінити для детермінованих тестів.

`closures.py` містить три замикання:
- `make_counter(start)` — незалежний лічильник зі змінним станом через nonlocal;
- `make_backoff(delay, factor)` — політика `delay * factor**(i-1)` для номера
  невдалої спроби i від 1; factor=1 задає фіксовану затримку;
- `make_logger(prefix, sink)` — логер із захопленим префіксом і sink.

Початкова затримка має бути скінченною та невід’ємною, factor — скінченним
і не меншим за 1. Політика не зберігає номер спроби: він передається явно,
тому повторні запуски не успадковують прогрес backoff.

## Декоратори

У `decorators.py` реалізовано три фабрики параметризованих декораторів.
Кожна обгортка використовує `functools.wraps`, ParamSpec і TypeVar.

`timed(label, unit, logger, clock)` вимірює час через ін’єктований clock.
Логування в finally відбувається як при успіху, так і при винятку.
Одиниці: s, ms або us. Logger має бути надійним: його власний виняток
може перервати обгортку. Годинник повинен бути монотонним.

`retries(attempts, delay_policy, exceptions, sleep, logger)` викликає задачу
не більше attempts разів. Після невдалої спроби i політика визначає паузу.
Після останньої невдалої спроби паузи немає; початковий виняток повторно
піднімається через bare raise. Невказані винятки поширюються одразу.
Некоректна пауза (від’ємна/нескінченна/NaN) відхиляється до sleep.
Exceptions — непорожній tuple класів Exception. Усі аргументи мають
відповідати анотаціям типів. Великі степені backoff можуть перевищити
діапазон float; таку помилку політики не повторюємо.

`cached(ttl, time_fn)` кешує успішні результати для хешованих args/kwargs.
Порядок keyword-аргументів у ключі нормалізується сортуванням. Позиційна
та іменована форми виклику є окремими ключами; стандартні значення не
нормалізуються. Рівні аргументи за правилами Python можуть ділити запис.
Нехешовані аргументи спричиняють TypeError. Винятки не зберігаються.
TTL починається після успішного обчислення; на межі `now == expiry` запис
вважається простроченим. TTL=None — безстроково, TTL=0 — без повторного
використання. Доступні `cache_clear()` та `cache_invalidate(predicate)`.
Типізований Protocol описує виклик і методи кешу.

Lock захищає операції зі словником. Обчислення відбувається поза lock:
паралельні однакові запити можуть обчислюватися повторно, а незавершений
виклик може знову наповнити кеш після очищення. Предикат інвалідації має
бути чистим і не звертатися до того самого кешу. Результат повертається
як збережений об’єкт, тому для кешування варто обирати незмінні результати.
Неактуальні записи видаляються при зверненні до відповідного ключа або
через інвалідацію/очищення; фонової очистки немає.

## Порядок композиції

```python
@timed(logger=log, clock=clock)
@retries(attempts=4, delay_policy=policy, sleep=fake_sleep, logger=log)
def task():
    ...
```

Декоратори застосовуються знизу вгору, виклик проходить зверху вниз.
Зовнішній timed вимірює весь цикл повторів. Якщо retries зовні, timed
виконується для кожної спроби, включно з невдалими. Обидва випадки
перевірено тестами. Зовнішній timed також виконався б при кеш-хіті, якщо
cached розмістити всередині; порядок визначає, які обгортки відвідуються.

## Результат демонстрації

Задача завершується успіхом із четвертої спроби. Фіксовані паузи:
`[0.5, 0.5, 0.5]`; експоненційні: `[0.5, 1.0, 2.0]`.
У main.py `sleep=waits.append`: зберігається план очікувань без реального
сну. Clock повертає задані значення 0 і 0.012; надруковані 12 ms є
навчальною демонстрацією ін’єкції, а не заміром швидкодії.

У демонстрації TTL перший і повторний виклики дають «обчислення 1»;
на точній межі TTL — «обчислення 2», після інвалідації — 3, після clear — 4.
Clock, sleep і logger у тестах підмінені; мережевих викликів немає.

## Висновок

Замикання ізолюють стан і конфігурацію кожного екземпляра. Фабрики
декораторів дозволяють змінювати політики повторів і залежності без
переписування задачі. Wraps зберігає метадані та зв’язок __wrapped__.
Стан кешу й лічильників та ефекти logger/sleep явно відокремлені від
бізнес-результату. Повторювати слід задачі, для яких повторний виклик
допустимий: декоратор retries сам не забезпечує ідемпотентності.
